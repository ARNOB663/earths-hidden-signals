## 6. "× times normal for this date" — exact definition

For a cell and window `W ∈ {1,3,7}` ending on the latest IMERG day `D`:

- `rain(D,W)` = sum of daily values for days `D-W+1 … D`, from the **same product as the baseline** (gate (c): normally IMERG Late, so live and baseline agree; the recorded `product` is shown on every surface).
- Baseline set `B(D,W)` = for every baseline year `y`, `rain(date(y, doy(D)), W)` where `doy` ranges over `doy(D) − 15 … doy(D) + 15` (day-of-year with leap handling; the 1/3/7-day window never crosses into the other year's data).
- **Year requirement:** baseline needs **≥ 15 distinct years** (config `baselineYearsMin`) **and** n ≥ 300, else Grey `baseline-small`. In replays, the event year is excluded from its own baseline.
- `normal(D,W)` = **median of wet-day baseline values**, wet-day = `rain ≥ 1 mm` (config `wetDayMinMm`). If `count(wet-day) < 30` ⇒ `ratio = null`.
- `ratio(D,W) = rain(D,W) / normal(D,W)`; shown as `"2.6× normal for this date"`. When `ratio` is null the UI says "unusually wet for this date" with mm only, confidence capped Low.
- Percentile = share of **all** baseline values `≤ rain(D,W)` (zeros included).
- Thresholds per §6 of rev. 5 (Yellow p≥85 & ratio≥2 & mm≥10; Red p≥96 & ratio≥3 & mm≥25; status = max over windows).
- No arithmetic mean anywhere; `/about` shows this text plus the exact config numbers.

**Unit test:** a hand-computed fixture — 12 years, one cell, known daily series where `rain(D,3) = 42 mm`, wet-day median `= 15 mm` ⇒ ratio `2.8` asserted exactly; a second fixture with 4 wet days ⇒ `ratio:null`; a third with 14 years and n ≥ 300 ⇒ Grey `baseline-small`; a replay fixture where the event year's 500 mm is excluded and the ratio recomputed.

## 7. Backtest design (written before step 9)

- **Candidate events:** verified floods on different continents, dated before 2025-09-30, each inside an enabled tile, each with a start date from GDACS [M] cross-checked where possible with EONET/relief reports. List written in `spike_report.md` (§4a-i).
- **Split:** events dated **2010-09-30 or earlier** = TUNING (can move thresholds); events dated **after that** = REPORTING (thresholds frozen, never used for tuning). If the split leaves < 3 reporting events, all events are reporting-only and thresholds stay provisional.
- **Event area:** the set of cells whose centre is within **50 km** of the event's GDACS coordinates, or inside the GDACS footprint polygon when one is published (config `eventRadiusKm: 50`; the spike records each event's footprint so the radius can be tightened if GDACS gives a polygon).
- **Hit:** a **cell inside the event area** is Yellow or Red in any window on any day from event start − 3 days to event start (inclusive). Signals elsewhere in the tile do not count.
- **Miss:** no cell in the event area meets the hit rule.
- **Signals with no catalogued event (upper bound; flood catalogues are incomplete):** a Yellow/Red day in a cell inside a tuning/reporting **event area radius** with no catalogued event start within 3 days after it. The word "false alarm" is not used anywhere in UI, docs or data keys; the field is `unmatched_signals`.
- **Satellite-confirmed:** a hit whose event area also has a LANCE flood-water detection around the event (labelled beta / not confirmed absent).
- Reporting cells and events only; `/accuracy` shows each count with its denominator and "not enough events yet" when reporting events < 3.
