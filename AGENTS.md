Two independent parts: `analysis/` (Python pipeline) writes committed JSON into `web/public/data/`; `web/` (Next.js 16) reads it at build/request time. The website works without rerunning the pipeline.

## Commands

Web (from `web/`):
- `npm run dev`, `npm run build` (also type-checks — there is no separate typecheck script), `npm run lint`
- No test suite. Validate web changes with `npm run lint` and `npm run build`.

Analysis (from `analysis/`):
- `pip install -r requirements.txt` (needs `shapely` for country aggregation)
- `python -m pytest -q` — tests are `test_stats.py`, `test_country_signals.py` and `tests/` (intelligence engine)
- Single test: `python -m pytest -q test_stats.py::test_clear_trend_is_significant_with_correct_rate`
- Tests import modules directly, so run pytest from `analysis/` (no package/`PYTHONPATH` setup).

Pipeline order matters (later steps read earlier outputs):
`python build.py` → `build_hazards.py` → `cyclones.py` → `crosscheck.py` → `latest.py` → `intelligence.py` → `evaluate.py`.
`intelligence.py` and `evaluate.py` run offline from committed JSON; `intelligence.py --reproduce` must give byte-identical
output (CI checks it), and `--refresh` adds monthly series (network). All thresholds live in `analysis/intel/thresholds.py`;
never duplicate a threshold in TypeScript. `analysis/intel/` is a package on purpose: a top-level `calendar.py` would shadow
the standard library module that `build.py` and `latest.py` import.
`turning.py` (offline, after `build.py`) runs Pettitt change-point tests on every region series and writes `web/public/data/trends/turning.json`, shown on `/climate-trends` (tests: `test_turning.py`).
`twins.py` (Climate Twins, offline after the first run) reads the global `raw/gistemp` + `raw/gpcp` files, Natural Earth outlines in `raw/naturalearth/`, cached GDACS FL/DR/TC and `raw/events/glc.csv`, and writes `web/public/data/twins/{twins,series}.json` for `/climate-twins`; tests in `test_twins.py`. `cmip6_download.py` fetches NASA NEX-GDDP-CMIP6 South Asia subsets (6 models; historical 1995–2014, SSP2-4.5/SSP5-8.5 2041–2060) into `raw/cmip6/` via NCCS THREDDS NCSS (no login); `future.py` turns them into `web/public/data/future/outlook.json` for `/future-outlook` (per-model change vs its own 1995–2014 run, ensemble median/range/agreement, and how often today's 1-in-10 wet/dry/heavy-rain/hot years recur in 2041–2060; tests in `test_future.py`). It uses whichever models have complete files. `risk.py` (after `future.py`) fits a per-region logistic model of high-event years on the region's pre-assigned drivers, scores it on unseen years (leave-one-year-out Brier skill, leave-pair-out AUC, permutation test with Benjamini–Hochberg across regions) and projects odds only for regions that pass; writes `web/public/data/risk/model.json`, shown as the scorecard on `/future-outlook`; tests in `test_risk.py`.
`build.py` itself also runs `build_country_signals.py`, writing `web/public/data/maps/place-signals.json`. `build_hazards.py`, `latest.py`, and `crosscheck.py` all depend on `build.py` output; `crosscheck.py` re-reads `trends/zones.json`.

## Web notes

- Next.js 16 has breaking changes vs. training data; read `web/node_modules/next/dist/docs/` before writing code (see `web/AGENTS.md`, auto-generated by `next dev` — commit it rather than deleting).
- `web/CLAUDE.md` imports `web/AGENTS.md`. Root `CLAUDE.md` is a longer, partly stale summary — prefer this file and the code when they disagree.
- Pages: exactly seven primary routes — `/` (Home), `/signal` (Signal, the central feature: search, map, coverage, Watch Level, historical frequency), `/gap` (coverage audit and missing datasets), `/replay` (event replay + what-if threshold slider), `/accuracy` (backtest metrics, calibration, failed tests), `/act` (preparedness, shareable cards, SMS-style messages), `/watch` (saved locations, browser-only preferences) — plus `/climate-trends`, `/methods` and `/for-organizations` (footer). `/climate-trends` is the trend-detection page (what is changing, where, by how much, is it significant): `components/trends/TrendExplorer.tsx` with `TrendMap`/`SeriesChart`, reading `public/data/trends/` (manifest/zones/crosscheck server-side, per-square grids and series fetched client-side). It is linked from Home and the footer, not a nav tab, so the seven-tab contract holds; the retired `/trends` redirects to it. Retired routes (`/trends`, `/hazards`, `/monitoring`, `/locations`, `/countries`, `/country/[slug]`, `/location/[id]`, `/explore`, `/findings`, `/signals*`, `/about`) 308-redirect to a surviving page via `web/next.config.ts`; `scripts/signals/tests/test_guardrails.py` enforces the seven tabs, the redirects and that no component links to a retired route.
- `/signal/[id]` uses `dynamicParams = false`; IDs come from `web/public/data/signals/places.json` (built by `scripts/signals/place.py`). Data pages set `revalidate = 86400`.
- Signal data is read through `web/src/lib/signals/model.ts` and `web/src/lib/signals/backtest.ts`. Watch Levels live in `web/src/lib/signals/level.ts`; historical frequency (with sample size and Wilson interval) in `web/src/lib/signals/`. Nothing classifies in React.
- **Sample honesty:** the committed daily rain readings are currently fixed samples (`sample: true` per cell) on a fixed clock date. `model.ts` derives `sample` from the cells (not the possibly-stale `meta.json`); every surface that shows those values renders `SampleNotice` or a sample-labelled field. Do not describe them as live IMERG observations. Coverage counts, historical case sizes and the Accuracy backtest are computed from real datasets.
- Outlook (7-day forecast) is withheld unless it meets the evidence rules; while it fails, pages show "Not enough evidence here". The external outlook files under `places/{id}.json` exist but must not be presented as a forecast.
- Intelligence data is read server-side through `web/src/lib/intelligence/data.ts`, which throws at build time if a required key is missing. `web/src/lib/intelligence/conclude.ts` only maps pipeline values to labels; it never classifies.
- Server-side JSON reads go through `web/src/lib/data.ts` (Node `fs`, `process.cwd()/public/data/...`; only the trend manifest/zones/crosscheck readers), `lib/signals/{model,data,backtest}.ts`, `lib/intelligence/data.ts` and `lib/geography/data.ts`, not fetch. Large per-cell series files are fetched from `/data/...` by client components.
- i18n (English/Bangla) lives in `web/src/lib/i18n.tsx` (`<T>`), `bn.ts`, plus `lib/signals/level.ts` (level vocabulary) and `geography/index.json` (`nameBn`). There is no `names.ts`.
- Shared page primitives: `components/ui/primitive.tsx` (`Eyebrow`), `components/signal/levels.tsx` (`Stat`, `CoverageStats`, badges, `formatFrequency` is in `lib/signals/level.ts`). Do not re-declare these per page.
- `web/src/lib/layers.ts` holds the GIBS WMTS root and the (currently unrendered) layer definitions; `components/map/baseMap.ts` is shared by every map. The Map Explorer (GIBS heat/rain/soil/greenness/forest-loss layers, time slider, compare and difference views) was removed on 2026-11-06 and restored on 2026-11-09 as `/satellite-map` (footer + Home link, not a tab); the retired `/explore` redirects there. Its place figures read `maps/place-signals.json` keys like `temperature_annual`.
- `web/next.config.ts` holds the retired-route redirects (all `permanent: true`); images/metadata are defined per route.

## Data

- Committed outputs: `web/public/data/signals/` (places, areas, coverage, frequency, backtest, accuracy, provenance), plus the underlying `trends/`, `hazards/`, `maps/`, `latest.json`, `intelligence/`, `geography/`. `build_signal_scores.py` writes `coverage.json` + per-country `areas/` + `area-search.json`; `place.py` writes `places.json` + `places-map/`. Raw downloads under `analysis/raw/` and pipeline logs under `analysis/logs/` are gitignored.
- Shared regions are defined in `analysis/zones.json`; trend and hazard builds both use it.
- Regenerating data changes committed JSON — rerun `npm run build` afterwards to confirm the site still builds.
