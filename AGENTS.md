# AGENTS.md

Two independent parts: `analysis/` (Python pipeline) writes committed JSON into `web/public/data/`; `web/` (Next.js 16) reads it at build/request time. The website works without rerunning the pipeline.

## Commands

Web (from `web/`):
- `npm run dev`, `npm run build` (also type-checks — there is no separate typecheck script), `npm run lint`
- No test suite. Validate web changes with `npm run lint` and `npm run build`.

Analysis (from `analysis/`):
- `pip install -r requirements.txt` (needs `shapely` for country aggregation)
- `python -m pytest -q` — tests are `test_stats.py`, `test_country_signals.py` and `tests/` (intelligence engine)
- Single test: `python -m pytest -q test_stats.py::test_clear_trend_is_significant_with_correct_rate`
- Tests import modules directly, so run pytest from `analysis/` (no package/`PYTHONPATH` setup).

Pipeline order matters (later steps read earlier outputs):
`python build.py` → `build_hazards.py` → `cyclones.py` → `crosscheck.py` → `latest.py` → `intelligence.py` → `evaluate.py`.
`intelligence.py` and `evaluate.py` run offline from committed JSON; `intelligence.py --reproduce` must give byte-identical
output (CI checks it), and `--refresh` adds monthly series (network). All thresholds live in `analysis/intel/thresholds.py`;
never duplicate a threshold in TypeScript. `analysis/intel/` is a package on purpose: a top-level `calendar.py` would shadow
the standard library module that `build.py` and `latest.py` import.
`build.py` itself also runs `build_country_signals.py`, writing `web/public/data/maps/place-signals.json`. `build_hazards.py`, `latest.py`, and `crosscheck.py` all depend on `build.py` output; `crosscheck.py` re-reads `trends/zones.json`.

## Web notes

- Next.js 16 has breaking changes vs. training data; read `web/node_modules/next/dist/docs/` before writing code (see `web/AGENTS.md`, auto-generated by `next dev` — commit it rather than deleting).
- `web/CLAUDE.md` imports `web/AGENTS.md`. Root `CLAUDE.md` is a longer, partly stale summary — prefer this file and the code when they disagree.
- Signals (separate pipeline in `scripts/signals/`, its own tests): `/signals` (map + ranked list), `/signals/place?id=…`
  (Before/Now/Next/Trust/Action strips, built by `scripts/signals/place.py` into `web/public/data/signals/places.json`),
  `/signals/evidence`, `/accuracy` (Trust evidence), `/watch`. `place.py` is offline and byte-stable; only
  `place.py --refresh` uses the network (Open-Meteo outlook + rain archive, GDACS flood years) and writes
  `web/public/data/signals/places/{id}.json`. Run it from `analysis/.venv`; see `scripts/signals/README.md`.
- Routes: `/`, `/monitoring`, `/locations`, `/location/[id]`, `/explore`, `/trends`, `/hazards`, `/findings`, `/methods`, `/countries`, `/country/[countrySlug]`. `/location/[id]` and `/country/[countrySlug]` use `dynamicParams = false`; location IDs come from `web/public/data/intelligence/locations.json` (cities from `web/src/lib/places.ts`, read by the pipeline), so a new place needs a pipeline run. Data pages set `revalidate = 86400`.
- Intelligence data is read server-side through `web/src/lib/intelligence/data.ts`, which throws at build time if a required key is missing. `web/src/lib/intelligence/conclude.ts` only maps pipeline values to labels; it never classifies.
- Server-side JSON reads go through `web/src/lib/data.ts` (Node `fs`, `process.cwd()/public/data/...`), not fetch. Large per-cell series files are fetched from `/data/...` by client components.
- i18n (English/Bangla) lives in `web/src/lib/i18n.tsx` (`<T>`), `bn.ts`, and `names.ts` — not `locale.ts`/`LanguageContext` as older docs say.
- Map Explorer layers are in `web/src/lib/layers.ts`; `web/src/lib/gibs.ts` fetches GIBS catalog server-side with 1-day revalidation. Forest-loss tiles are decoded client-side in `web/src/components/map/forestLossLayer.ts`. Explorer state lives in URL query params.
- `web/next.config.ts` is intentionally empty; images/metadata are defined per route.

## Data

- Committed outputs: `web/public/data/trends/`, `web/public/data/hazards/`, `web/public/data/maps/`, `web/public/data/latest.json`, `web/public/data/intelligence/`. Raw downloads under `analysis/raw/` and pipeline logs under `analysis/logs/` are gitignored.
- Shared regions are defined in `analysis/zones.json`; trend and hazard builds both use it.
- Regenerating data changes committed JSON — rerun `npm run build` afterwards to confirm the site still builds.
